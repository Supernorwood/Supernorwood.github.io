02 / Troubleshooting journal

Root causes. Not surface fixes.

Selected engineering investigations from a personal AI-assisted automation system. Each example highlights a failure mode, the corrective approach, and the reliability principle behind it.

Classification / logic

Conflicting classification rules

Failure: The system treated two related but distinct criteria as interchangeable, producing an overconfident eligibility classification.

Fix: Separate independent constraints, define clear decision precedence, and route unresolved cases to an explicit verification state. Add regression tests for ambiguous inputs.

Data integrity

Ambiguous states corrupt decisions

Failure: A broad skip category combined missing evidence with genuine disqualifiers, obscuring why records were excluded.

Fix: Introduce typed decision reasons and preserve historical state rather than silently rewriting earlier evaluations or outcomes.

Access / reliability

Access failures are not missing data

Failure: External sources returned access restrictions, creating a risk that unavailable data would be misclassified as nonexistent.

Fix: Use permitted source interfaces, respect access controls and 403/429 responses, and distinguish access failure from an actual absence of data.

Document quality

Document validation beyond appearance

Failure: Text extraction split important technical terms, while a Windows layout-verification tool lacked a required command option.

Fix: Add targeted token-integrity checks and a compatible layout-verification fallback instead of relying on visual inspection alone.

AI output validation

Confident wording without evidence

Failure: AI-generated narratives risked introducing unsupported details, claims, or numerical outcomes.

Fix: Strengthen evidence-grounding rules and flag unverified metrics for human review. Plausible output is not verified output.

Human-in-the-loop

Separate preparation from execution

Failure mode: A workflow can generate an output without the downstream action actually taking place. Treating both as the same state produces unreliable records.

Control: Keep consequential actions behind explicit human confirmation, preserve state transitions, and resolve ambiguous record matches before recording outcomes.
